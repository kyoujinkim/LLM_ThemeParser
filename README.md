# LLM_ThemeParser

기업의 사업 문서와 뉴스 헤드라인을 검색·재정렬하고, LLM을 이용해 **기업과 투자 테마의 연결 근거**를 정리하는 연구 도구입니다. 단순 단어 일치보다 문맥과 근거 문서를 함께 살펴보는 것을 목표로 합니다.


## 연구 결과

2024-11-05 보고서는 LLM이 산출한 기업·테마 연관도를 테마 ETF와의 수익률 상관관계로 점검합니다. 연관도는 기업이 테마의 공급자·수요자에 가까운지를 구분하는 점수입니다.

| 테마·ETF | 공급자 연관도 조건 | 종목군·ETF 수익률 상관계수 |
|---|---|---:|
| 2차전지 셀·부품 / TIGER 2차전지테마 | 50 초과 | 0.7493 |
| 2차전지 셀·부품 / TIGER 2차전지테마 | 90 초과 | 0.8148 |
| SMR 설계·제조 / ACE 원자력테마딥서치 | 50 초과 | 0.7028 |
| SMR 설계·제조 / ACE 원자력테마딥서치 | 80 초과 | 0.6951 |

표 7~8의 74.93, 81.48 등 백분율 표기를 상관계수의 0~1 스케일로 변환했습니다. 보고서는 52주 이동 상관 추이도 제시합니다. 2차전지는 높은 공급자 연관도에서 더 높은 ETF 연동성을 보였지만 SMR은 점수를 높일수록 항상 상관이 커지지는 않았습니다.

이 결과는 테마 연관도의 시장 행동상 일관성을 점검한 사례이며, 정답 라벨 기반 분류 정확도나 미래 투자 초과수익률이 아닙니다. ETF 구성종목 중복·업종 노출·평가 기간 차이를 통제한 추가 검증이 필요합니다.

## 처리 흐름

```text
대상 기업 목록 + 테마 설명·검색 핵심어
  → 사업 문서 또는 뉴스 검색
  → 관련 문서 재정렬
  → LLM의 테마 관련성 설명
  → 기업별 결과 CSV·재시작 로그
```

| 파일 | 역할 |
|---|---|
| `main.py` | 대상 기업·테마 설정과 반복 실행 |
| `defineGPT.py` | `GptAgent`, 테마 정의·문서 결합·응답 생성 |
| `parseNews.py` | 뉴스 검색·파싱 |
| `reranker.py`, `retrieveScore.py` | 검색 결과 재정렬·관련성 처리 |
| `wikiScraping.py` | 테마 정의용 정보 수집 보조 |
| `241031_종목_테마_분류_알고리즘.pdf` | 연구 배경과 알고리즘 설명 |

## 설치·입력

```bash
python -m pip install -r requirements.txt
```

LangChain·모델 API·재정렬 모델의 버전과 접근 권한을 확인해야 합니다. 로컬 모델은 CPU/GPU·메모리·모델 다운로드 조건에 따라 처리 시간이 달라집니다.

1. `data/KOSPI_L+M.xlsx`의 `list` 시트에 기업 목록을 준비합니다. 현재 코드는 첫 열을 기업 코드 인덱스로, `Name` 열을 기업명으로 읽습니다.
2. `data/buss_detail/` 등 사업 문서 경로를 `GptAgent.run()`의 입력 계약에 맞춰 준비합니다.
3. 비공개 `data/config.ini`의 `[section] OPENAI_API_KEY`를 설정합니다. 실제 값은 커밋하지 않습니다.
4. `main.py`의 `theme`, `theme_key`, 언어·모델·reranker·device를 분석 목적에 맞게 변경합니다.

테마 설명과 검색 핵심어가 다르면 수집 근거도 달라질 수 있습니다. 현재 파일에 들어 있는 예시 설정이 모든 테마에 적합한 기본값은 아닙니다.

## 실행

저장소 루트에서 실행합니다.

```bash
python main.py
```

현재 기본 흐름은 `document`와 `headline` 경로를 순차 실행합니다. 외부 뉴스·모델 API 요청이 발생할 수 있습니다. `data/log_doc.txt`, `data/log_head.txt`를 통해 중간 결과를 재사용하므로, 기업 순서·테마·모델을 바꿀 때 로그가 다른 실험과 섞이지 않게 관리해야 합니다.

## 산출물과 사용법

`data/<theme>_<typeinfo>_result.csv`에 `Code`, `Name`, `Detail` 형식의 결과를 저장합니다. `Detail`은 LLM의 설명이며 그 자체가 검증된 매출 비중·테마 확률·투자 점수는 아닙니다.

기업의 직접 사업 노출, 간접 수혜, 단순 뉴스 언급을 구분하고 근거 원문과 대조하면 테마 유니버스 구성과 수동 검토 시간을 줄이는 데 활용할 수 있습니다. 수익률 검증에 사용할 때는 문서·뉴스의 공개 시점과 검색 시점을 고정해야 합니다.

## 한계·자료 이용

검색 누락·재정렬 편향·LLM 환각·기업명 중의성에 영향을 받습니다. 결과에 근거·날짜·모델·프롬프트를 함께 기록하는 것이 좋습니다. 뉴스·사업 문서의 수집·외부 전송·재배포 권한과 코드의 재사용 범위는 별도로 확인하세요.
